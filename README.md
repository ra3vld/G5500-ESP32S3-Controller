# G5500 Controller

Прошивка контроллера антенных поворотных устройств Yaesu G-5500, G-800DXA и независимых DC-приводов. Поддерживает ESP32 WROOM/WROVER, [ESP32-C3 без дисплея](docs/boards/esp32-c3.md), ESP32-S3, ESP32-S2, WT32-ETH01 с Ethernet, [Waveshare ESP32-S3-ETH с камерой](docs/boards/waveshare-esp32-s3-eth.md), CrowPanel 2.1, [ESP32-3248S035C](docs/boards/esp32-3248s035c.md) и [сенсорный пульт ESP32-2424S012C-Y(B)](docs/boards/esp32-2424s012c.md).

**ESP32-C3 и ESP32-S2 ограниченно подходят для полнофункционального использования этой прошивки.** При совмещении управления, веб-интерфейса и сетевых сервисов ограничены запас внутренней RAM и время единственного ядра. Для полного набора функций с дисплеем и несколькими сетевыми клиентами выбирайте ESP32-S3 с PSRAM. Перед выбором C3 или S2 ознакомьтесь с [ограничениями этих плат](docs/setup/configuration.md#ограничения-esp32-c3-и-esp32-s2).

## Возможности

- AZ и EL с независимой калибровкой, стандартными или произвольными диапазонами, возможностью смещения нулевой точки.
- Штатные блоки Yaesu, отдельные PWM-приводы и BTS7960.
- GS-232, rotctld, N1MM и PstRotator UDP(в том числе UR5EQF, 5MContest, SkyRoof, TR4W, DXLog.net, Log4OM 2 и Gpredict.); HTTP, WebSocket и командный API.
- Веб-управление, предустановки, кнопки направлений и аналоговый джойстик.
- Дисплеи ILI9341/XPT2046, LCD1602, CrowPanel 2.1, GC9A01/CST816 на ESP32-2424S012C ST7796/GT911 на ESP32-3248S035C и [внешний ST77916/CST816S 360×360](docs/boards/waveshare-1.85-qspi.md) на ESP32/ESP32-S3.
- Возможность подключения удаленного (HUD) пульта по сети или UART для контроля удаленного поворотного устройства.
- Практически полное переконфигурирование подключенного оборудовния без перепрошивки(тип поворотки, GPIO, дисплей, BLuetooth).
- OTA обновление по Wi-Fi.
- Режим имитации движения для отладки
- Простой регулятор или каскадный ПИД, автотюн регуляторов движения, режим активного удержания позиции.
- Ручной и Авторежим. В ручном режиме команда из внешней программы по умолчанию ждёт подтверждения пользователя; возможно включить автоследование отдельно для каждого протокола.

Для Classic ESP32 с одновременной работой Wi-Fi, веба и встроенного Bluetooth
предусмотрены отдельные [профили `esp32_spp` и `esp32_spp_hud`](docs/boards/esp32-spp.md).
Они используют прямое управление PWM без PID, автотюна и рампы; веб сохраняет
настройки, калибровки и сброс ошибок. Вариант `_hud` добавляет пульт по UDP.

## Начало работы

Начните с [первого запуска](docs/quickstart.md): выбор платы и подключения → сборка и USB-прошивка → настройка оборудования → калибровка → управление.

Arduino IDE: откройте `G5500_Fork/G5500_Fork.ino` вместе с его папкой. Плату и Partition Scheme выбирайте по [инструкции для Arduino IDE 2.x](docs/build.md#arduino-ide-2x).

Для ESP32-S3 DevKitC-1 N16R8 без дисплея:

```sh
pio run -e esp32s3_n16r8
```

Это только сборка. [Запись через USB](docs/build.md#первая-прошивка-через-usb), [выбор других плат](docs/setup/configuration.md#выбор-конфигурации), [вся документация](docs/index.md).

### Прошивка через GUI pioarduino

Установите [pioarduino IDE в VS Code](docs/quickstart.md#установка-pioarduino--platformio), откройте корень проекта с `platformio.ini` и панель **Pioarduino → Project Tasks**. Отключите силовое питание привода, подключите плату USB-кабелем с передачей данных, выберите её последовательный порт в нижней панели и закройте Serial Monitor.

Цифры на скриншоте соответствуют шагам ниже. Если текущий профиль рассчитан на другой чип, выберите профиль своей платы по шагу 2 ещё до очистки Flash.

1. **Очистить Flash:** откройте **Platform → Erase Flash** и дождитесь `SUCCESS` в терминале. Очистка удаляет прошивку, настройки и калибровки; выполняйте её для установки с полным сбросом. При обычном обновлении этот шаг можно пропустить.
2. **Выбрать профиль платы:** нажмите **env:…** в нижней строке VS Code и выберите [окружение своей платы](docs/setup/configuration.md#выбор-конфигурации). На скриншоте показан `env:esp32_2424s012c` для ESP32-2424S012C-Y(B). **Default** использует `default_envs` из `platformio.ini` и может не соответствовать подключённой плате.
3. **Залить прошивку:** в задачах выбранного профиля нажмите **General → Upload**. Дождитесь окончания сборки и записи с результатом `SUCCESS`.
4. **Залить файловую систему, если она используется:** для того же профиля выберите **Platform → Upload Filesystem Image** и дождитесь `SUCCESS`. **В текущем проекте этот шаг пропустите:** отдельной папки `data/` нет, веб-интерфейс уже входит в прошивку. Этот пункт GUI нужен для сборок с отдельными файлами в `data/`; порядок их загрузки описан в [справке PlatformIO](https://docs.platformio.org/en/latest/platforms/espressif32.html#uploading-files-to-file-system).

![Действия в GUI pioarduino: 1 — Erase Flash, 2 — выбор профиля, 3 — Upload, 4 — Upload Filesystem Image](docs/images/pioarduino-gui-upload.png)

После записи при необходимости нажмите **RESET/EN** и выполните [первое подключение и настройку](docs/quickstart.md#первое-подключение). Если загрузчик не отвечает, используйте [порядок входа в BOOT и выбора USB-порта](docs/build.md#первая-прошивка-через-usb).
