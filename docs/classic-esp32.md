# Классический ESP32 WROOM/WROVER

Профиль `BOARD_ESP32` рассчитан на обычные ESP32 DevKit, DevKitC и NodeMCU с Flash от 4 MB и доступными GPIO из таблицы. Общая распиновка подходит модулям WROOM и WROVER: GPIO6…11 и GPIO16/17 не используются, PSRAM не требуется. Платы со встроенными экранами, SD-картой или другой периферией нужно сверять отдельно. [Ограничения DevKitC и WROVER у Espressif](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32/esp32-devkitc/user_guide.html).

## Подключение

| Назначение | GPIO |
|---|---|
| ADC обратной связи AZ / EL | 34 / 35 |
| AZ отрицательное / положительное, LEFT / RIGHT | 25 / 26 |
| EL отрицательное / положительное, DOWN / UP | 14 / 27 |
| AZ / EL скорость либо ENABLE | 32 / 33 |
| USB-UART0 RX / TX | 3 / 1 |
| Внешний HC-05: RX ESP32 / TX ESP32 / STATE | 39 / 5 / 15 |
| Подтверждение ожидающей цели | 0, кнопка BOOT |
| TFT MOSI / SCK / MISO | 23 / 18 / 19 |
| TFT CS / DC / RST | 21 / 22 / 4 |
| XPT2046 CS / IRQ | 13 / 36 |
| LCD1602 RS / E | 21 / 22 |
| LCD1602 D4 / D5 / D6 / D7 | 23 / 18 / 19 / 4 |

TFT и параллельный LCD1602 — альтернативные сборки; LCD RW соединяется с GND. Для LCD с логикой 5 В сохраняется требование согласования уровней. Светодиодная индикация по умолчанию отключена, поскольку её GPIO различаются между платами. GPIO34…39 — только входы, без внутренних подтяжек. Обратная связь использует ADC1 и работает одновременно с Wi-Fi; на входы нужны делитель и защита согласно [аппаратной документации](hardware.md).

YAESU, SEPARATE_PWM и BTS7960 сохраняют свои назначения сигналов и правила подключения. Схемы S3 показывают другую нумерацию GPIO: переносите соединения по названиям сигналов, используя эту таблицу. В YAESU GPIO33 не используется; в G-800DXA выходы EL остаются выключенными.

## Bluetooth и USB

При `BLUETOOTH_ENABLED=1` и `BLUETOOTH_MODE=BT_AUTO` (или `BT_ESP32_SPP`) ESP32 запускает встроенный Bluetooth Classic SPP с именем **G5500-Rotator**. BLE отключён. На ПК или Android выполнить обычное сопряжение; ввод PIN или подтверждение на контроллере не нужны. Скорость виртуального COM-порта не задаёт скорость радиолинка. На S2/S3 этот профиль не применим: там сохраняется внешний HC-05.

Для внешнего модуля задайте `BLUETOOTH_ENABLED=1` и `BLUETOOTH_MODE=BT_HC05` в `build_config.hpp`. В этой сборке встроенный SPP не запускается. HC-05 использует отдельный UART1, 9600 бод, 8N1: **TXD модуля → GPIO39**, **RXD модуля ← GPIO5**, **STATE → GPIO15**, общий GND. Логические сигналы должны иметь уровень 3,3 В; питание VCC выбирайте по конкретной плате модуля. GPIO не пересекаются с приводом, UART0, TFT/touch или LCD1602 и не занимают GPIO16/17 WROVER.

GPIO5 и GPIO15 — strapping-выводы. LOW на STATE/GPIO15 при сбросе подавляет ROM-загрузочный текст UART0; GPIO5/15 также задают тайминги неиспользуемого SDIO slave. Назначения приведены в [даташите Espressif, Boot Configurations](https://documentation.espressif.com/esp32_datasheet_en.html). Состояние соединения HC-05 читается с STATE; MAC модуля через обычный UART неизвестен и в вебе не показывается.

```sh
python3 tools/build_platformio.py --env esp32_4mb --bluetooth 1 --bluetooth-mode hc05
```

USB-UART0 и Bluetooth принимают GS-232: положение, STOP, направления, цели и калибровку. Числовые внешние цели в ручном режиме по умолчанию ожидают подтверждения; настройка автоследования GS-232 позволяет выполнять их сразу по USB-UART0 и Bluetooth. Завершайте команды CR, LF или CRLF; длина строки — до 512 байт. При разрыве SPP незавершённый ввод и ожидающие отправки ответы отменяются. Порядок работы описан в [инструкции управления](usage.md).

USB-мост платы использует GPIO3/1: GS-232 на 9600 бод и загрузка прошивки. ROM при сбросе может выдавать загрузочный текст на 115200 бод. Журнал приложения доступен через веб по `/diaglog`.

Для встроенного SPP веб показывает **Bluetooth MAC** — его можно скопировать в настройки Look4Sat. «Bluetooth-соединение» означает активную связь с телефоном, «Канал SPP» — открытый последовательный канал приложения. Сохранённое сопряжение Android само по себе не означает активного соединения. Для HC-05 состояние берётся с STATE; MAC внешнего модуля через этот UART недоступен.

## Wi-Fi

Без встроенного SPP профиль Wi-Fi использует 8 статических приёмных буферов и лимиты по 64 динамических буфера приёма и передачи. Динамические буферы занимают память только на время обработки пакетов. Вариант со встроенным SPP сохраняет отдельный экономный профиль. Имя активного профиля (`buffered`, `compact` или `standard`) видно в диагностике `H4`.

При `ESP32_FORCE_AP_STA=0` контроллер подключается к роутеру. Если настройки отсутствуют или связь потеряна, запускается резервная сеть `G5500-Rotator-XXXXXX`; в роли HUD — `G5500-HUD-XXXXXX`. После восстановления связи с роутером резервная AP отключается. Для постоянной AP вместе с STA задайте `ESP32_FORCE_AP_STA=1`. Этот режим расходует больше внутренней памяти, особенно при встроенном SPP.

В режиме общей точки доступа для HUD устройство сохраняет AP независимо от этого флага. Настройка сети и интервалы повторного подключения описаны в [разделе Wi-Fi](usage.md#подключение-wi-fi).

## Диагностика

Если веб недоступен, откройте монитор USB-UART на **9600 бод** и отправьте `H4` с окончанием CR или LF. Ответ передаётся построчно; дождитесь завершения перед следующей командой. Журнал последних сообщений также доступен по `/diaglog`.

| Поле H4 | Как использовать |
|---|---|
| `elf` | Идентификатор загруженной сборки; приложите его к сообщению о неисправности |
| `HEAP free/min/max` | Свободная внутренняя память, минимум с момента запуска и наибольший свободный блок |
| `PSRAM available/total/free/min/max` | Доступность и объём внешней памяти; `available=no` также возможно при отключённой PSRAM или ошибке её запуска |
| `WIFI status=3`, `savedSSID=yes` | Подключение к роутеру и наличие сохранённых настроек сети соответственно |
| `runtimeMode`, `apPolicy` | Фактический режим Wi-Fi и политика точки доступа |
| `HTTP txFailures`, `cause/errno/bytes` | Ошибки передачи веб-ответов; поля причины могут хранить предыдущую ошибку, поэтому смотрите изменение счётчика |
| `TCP timewait` | Закрытые TCP-соединения, временно сохраняемые сетевым стеком |
| `RUNTIME allocFailures`, `OOM` | Отказы выделения памяти; сохраните полный ответ при обращении за помощью |
| `loopMaxUs`, `loopsOver20ms` | Максимальная длительность рабочего цикла и число циклов дольше 20 мс |

Размеры памяти указаны в байтах. PSRAM учитывается отдельно от внутренней памяти. При проблемах с вебом или Bluetooth сравните показатели после запуска и после появления неисправности; единичный минимум памяти не показывает, продолжает ли её расход расти.

## Сборка

```sh
pio run -e esp32_4mb
pio run -e esp32_4mb_lcd
pio run -e esp32_4mb_tft
python3 tools/build_platformio.py --env esp32_4mb --bluetooth 1 --bluetooth-mode hc05
./tools/build_arduino.sh esp32
```

В Arduino IDE откройте `G5500_Fork/G5500_Fork.ino`, выберите ESP32 Dev Module, Flash 4 MB, DIO 40 MHz, PSRAM Disabled, Core Debug Level None и Partition Scheme **Huge APP (3MB No OTA/1MB SPIFFS)**. `BOARD_PROFILE=BOARD_AUTO` можно оставить.

В исходной папке таблица разделов выбирается через меню IDE. В копии, подготовленной `prepare_sketch.py`, файл `partitions.csv` имеет приоритет над меню. PlatformIO и CLI используют `partitions_esp32.csv` с одним разделом приложения 3 MB; OTA с этой разметкой недоступно. Для [OTA](ota.md) выбирайте `esp32_4mb_ota` или `esp32_8mb_ota` по физической памяти и размеру прошивки. Полная инструкция — в [build.md](build.md).
