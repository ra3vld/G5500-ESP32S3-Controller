# Классический ESP32 WROOM/WROVER

Профиль `BOARD_ESP32` рассчитан на обычные ESP32 DevKit, DevKitC и NodeMCU с Flash от 4 MB и доступными GPIO из таблицы. Общая распиновка подходит модулям WROOM и WROVER: GPIO6…11 и GPIO16/17 не используются, PSRAM не требуется. Платы со встроенными экранами, SD-картой или другой периферией нужно сверять отдельно. [Ограничения DevKitC и WROVER у Espressif](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32/esp32-devkitc/user_guide.html).

## Подключение

| Назначение | GPIO |
|---|---|
| ADC обратной связи AZ / EL | 34 / 35 |
| AZ отрицательное / положительное, LEFT / RIGHT | 25 / 26 |
| EL отрицательное / положительное, DOWN / UP | 14 / 27 |
| AZ / EL скорость либо ENABLE | 32 / 33 |
| USB-UART0 RX / TX | 3 / 1 |
| Подтверждение ожидающей цели | 0, кнопка BOOT |
| TFT MOSI / SCK / MISO | 23 / 18 / 19 |
| TFT CS / DC / RST | 21 / 22 / 4 |
| XPT2046 CS / IRQ | 13 / 36 |
| LCD1602 RS / E | 21 / 22 |
| LCD1602 D4 / D5 / D6 / D7 | 23 / 18 / 19 / 4 |

TFT и параллельный LCD1602 — альтернативные сборки; LCD RW соединяется с GND. Для LCD с логикой 5 В сохраняется требование согласования уровней. Светодиодная индикация по умолчанию отключена, поскольку её GPIO различаются между платами. GPIO34…39 — только входы, без внутренних подтяжек. Обратная связь использует ADC1 и работает одновременно с Wi-Fi; на входы нужны делитель и защита согласно [аппаратной документации](hardware.md).

YAESU, SEPARATE_PWM и BTS7960 сохраняют свои назначения сигналов и правила подключения. Схемы S3 показывают другую нумерацию GPIO: переносите соединения по названиям сигналов, используя эту таблицу. В YAESU GPIO33 не используется; в G-800DXA выходы EL остаются выключенными.

## Bluetooth и USB

HC-05, UART1 и сигналы RX/TX/STATE внешнего модуля исключены. При `BLUETOOTH_ENABLED=1` ESP32 запускает встроенный Bluetooth Classic SPP с именем **G5500-Rotator**. BLE отключён. На ПК или Android выполнить обычное сопряжение; ввод PIN или подтверждение на контроллере не нужны. Транспорт использует [асинхронный SPP API ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/v5.5.5/esp32/api-reference/bluetooth/esp_spp.html) без дополнительной задачи и очередей `BluetoothSerial`; скорость виртуального COM-порта не задаёт скорость радиолинка. На S2/S3 этот профиль не применим: там сохраняется внешний HC-05.

SPP принимает тот же GS-232, что USB-UART0, включая запросы положения, STOP, направления, цели и калибровку. Числовые внешние цели в ручном режиме ожидают подтверждения. Разделители CR/LF/CRLF, максимум 512 байт на строку; повреждённая или слишком длинная строка отбрасывается до разделителя. Входные команды формируются целиком до помещения в ограниченную очередь из восьми строк: перегрузка отбрасывает целые команды с записью в журнал. При разрыве SPP незавершённый ввод, ранее принятые команды и ожидающие ответы не переносятся в новое соединение. Передача ответов асинхронная, очередь ограничена восемью ответами; при переполнении ответ отбрасывается с записью в журнал, обработка управления продолжается.

Веб показывает встроенный SPP и фактическое подключение клиента. API сохраняет `build.bluetooth` и `btConnected`, добавляет неизменяемое поле `build.bluetoothBackend`: `ESP32_SPP`, `HC05` или `NONE`. При отключённом Bluetooth его объект и библиотека исключаются при сборке через `build_platformio.py`.

USB-мост платы использует GPIO3/1: GS-232 на 9600 baud и загрузка прошивки. Диагностика приложения остаётся в веб-журнале `/diaglog`. ROM при сбросе может выдавать загрузочный текст на 115200 baud; это не поток диагностики приложения. Ошибка запуска SPP записывается в журнал, USB и сетевое управление продолжают работать.

На классическом ESP32 журнал занимает фиксированные 2048 байт и сохраняет последние полные строки, чтобы работа Wi-Fi/SPP не исчерпывала heap растущими строками. S2/S3 сохраняют журнал на 160 строк. Если веб недоступен, отправьте `H4` с окончанием CR/LF через монитор порта на 9600 бод: ответ покажет свободную heap, минимум, наибольший блок, расходы этапов запуска и состояние Wi-Fi/NVS без пароля. Значение `WIFI status=3` означает подключение STA к роутеру; `savedSSID=yes` означает наличие загруженного SSID. Снятые на старте `beforeBT`, `afterBT`, `afterAP`, `afterWiFi`, `setup` и текущие `free`/`max` позволяют отличить расход запуска от последующего роста потребления.

## Сборка

```sh
pio run -e esp32_4mb
pio run -e esp32_4mb_lcd
pio run -e esp32_4mb_tft
python3 tools/build_platformio.py --env esp32_4mb --display tft --bluetooth 0 --drive bts7960
./tools/build_arduino.sh esp32
```

Для Arduino IDE откройте исходный `G5500_Fork/G5500_Fork.ino`, выберите ESP32 Dev Module, Flash 4 MB, DIO 40 MHz, PSRAM Disabled, Core Debug Level None и Partition Scheme **Huge APP (3MB No OTA/1MB SPIFFS)**. `BOARD_PROFILE=BOARD_AUTO` можно оставить. В исходной папке нет `partitions.csv`, поэтому IDE генерирует таблицу из выбранной схемы; отдельная копия не требуется. В старых копиях скетча удалите `partitions.csv`, если хотите использовать меню.

PlatformIO и сборочные скрипты используют `partitions_esp32.csv`: один factory-раздел приложения 3 MB, поскольку Wi-Fi + SPP превышают старый слот 1,97 MB. Второго OTA-слота нет; веб-OTA в текущей прошивке отсутствует. NVS остаётся на `0x9000`, разметки S2/S3 сохранены. `prepare_sketch.py --target esp32` остаётся доступен для отдельной копии с явно заданной разметкой проекта.

Сборки и тесты с имитацией Bluetooth проверяют код и границы транспорта. Сопряжение, совместная работа радио Wi-Fi/SPP, свободная runtime heap, дисплей, датчики и двигатель требуют проверки на конкретном устройстве.
