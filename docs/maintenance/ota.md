# Обновление прошивки по Wi-Fi

[Документация](../index.md)

После первой установки прошивки через USB откройте **Настройки → Обновление прошивки**. Устройство само проверяет физический объём flash, размер текущего приложения и установленную таблицу разделов. Проверка доступна и для контроллера, и для HUD.

Для OTA нужны два раздела приложения, каждый достаточного размера, и служебный раздел `otadata`. Если flash недостаточно, интерфейс показывает необходимый минимум в байтах и рекомендуемый объём модуля ESP32. PSRAM не заменяет flash. Если flash достаточно, но разметка неподходящая, установите таблицу с двумя разделами через USB. OTA не меняет таблицу разделов.

## Обновление через браузер

1. Соберите приложение для той же платы, дисплея и подключения привода. В PlatformIO нужен **`firmware.bin`**; в Arduino IDE используйте **Sketch → Export Compiled Binary** и выберите файл приложения `.ino.bin`.
2. Откройте раздел обновления и проверьте доступный размер раздела OTA.
3. Выберите `.bin` и нажмите **Обновить прошивку**. Файлы `firmware.factory.bin`, `merged.bin`, загрузчик и таблица разделов для OTA не подходят.
4. Дождитесь сообщения о проверке и перезагрузке, затем обновите страницу. Не отключайте питание во время записи.

В начале обновления контроллер немедленно останавливает привод. HUD отправляет STOP выбранному контроллеру; перед обновлением пульта убедитесь, что удалённая поворотка остановилась. До перезагрузки команды движения не обрабатываются. Настройки и калибровки остаются в NVS.

Если передача прервана, текущая прошивка остаётся загрузочной. Через 30 секунд без данных загрузка отменяется. Движение остаётся заблокированным: нажмите **Перезагрузить устройство**, восстановите связь и повторите обновление. После неудачного обновления по ArduinoOTA также перезагрузите устройство через этот раздел.

## ArduinoOTA

1. Подключите компьютер и устройство к одной локальной сети.
2. В разделе обновления нажмите **Включить ArduinoOTA на 10 минут**.
3. Выберите показанный сетевой порт `g5500-XXXXXX.local` в Arduino IDE. Введите временный пароль из веб-интерфейса.
4. Загрузите приложение для той же платы и дождитесь успешного завершения. При следующем включении сетевого порта пароль изменится.

Если сетевой порт не обнаружен, можно использовать `espota.py` из установленного Arduino-ESP32, передав IP устройства и временный пароль. Используйте отправитель из той же версии Arduino-ESP32. Нужна связь в обе стороны: ESP32 подключается к TCP-порту отправителя. Обновление файловой системы отключено.

Веб-интерфейс доступен участникам сети без отдельной авторизации; временный пароль ArduinoOTA также виден в нём. Используйте OTA в доверенной локальной сети.

## Платы и разметка

| Профиль PlatformIO | Физическая flash | Разметка приложения |
|---|---|---|
| `wt32_eth01` | 4 МиБ | Один раздел 3 МиБ, OTA недоступно |
| `esp32_3248s035c` | 4 МиБ | Один раздел 3 МиБ, OTA недоступно; обновление через USB |
| `esp32_2424s012c` | 4 МиБ | Один раздел 3 МиБ, OTA недоступно; обновление через USB |
| `esp32c3_4mb` | 4 МиБ | Один раздел 3 МиБ, OTA недоступно; обновление через USB/UART |
| `wt32_eth01_noweb` | 4 МиБ | Два раздела по 1 966 080 байт; ArduinoOTA по Ethernet/Wi-Fi |
| `esp32_4mb` | 4 МиБ | Один раздел 3 МиБ, OTA недоступно |
| `esp32_4mb_noweb` | 4 МиБ | Два раздела по 1 966 080 байт; ArduinoOTA через командный API |
| `esp32_4mb_ota_compact` | 4 МиБ | Два раздела по 1 966 080 байт; веб, MQTT/HA и браузерное OTA, без встроенного SPP |
| `esp32_8mb_ota` | 8 МиБ | Два раздела по 3 670 016 байт |
| `esp32s2_mini` и его варианты | 4 МиБ | Один раздел 3 МиБ, OTA недоступно; обновление через USB |
| `esp32s2_4mb_ota_compact` | 4 МиБ | Два раздела по 1 966 080 байт; веб, MQTT/HA и браузерное OTA |
| `esp32s3_n16r8`, `crowpanel_21`, `crowpanel_21_az` | 16 МиБ | Два раздела по 6 553 600 байт |

Универсальный ESP32-образ включает код SPP даже при выключенном Bluetooth. Для OTA выбирайте физические 8 МиБ и `esp32_8mb_ota`; на 4 МиБ доступны `esp32_4mb_noweb` и `esp32_4mb_ota_compact`. Компактные OTA-профили ESP32 и прежней S2 используют периодический HTTP-опрос вместо WebSocket, ArduinoOTA в них исключено. `--bluetooth 0` меняет начальное состояние, а не размер набора драйверов; для исключения SPP нужен `BLUETOOTH_SPP_SUPPORT=0`. Выбор 8 МиБ в настройках не увеличивает память модуля.

```sh
pio run -e esp32_8mb_ota
pio run -e esp32_4mb_noweb
```

Образ должен помещаться в каждый OTA-слот. Первую установку и смену разметки выполняйте [через USB](../build.md#первая-прошивка-через-usb); дальнейшие обновления используют только файл приложения. Настройки Flash и разделов — в [инструкции сборки](../build.md).

## HTTP API

- `GET /api/ota` — доступность, причина отказа, объёмы flash/приложения/раздела и минимальная flash в байтах, состояние передачи, токен текущей загрузки устройства. Ответ не кешируется.
- Для следующих POST передавайте заголовок `X-OTA-Token` со значением `token` из этого ответа.
- `POST /api/ota/start?size=<байт>` — начать загрузку приложения.
- `POST /api/ota/write?offset=<байт>` — передать очередной блок бинарных данных, не более `chunkBytes` из статуса. Смещение должно совпадать с количеством уже принятых байтов. Повтор блока после потери ответа не поддерживается: отмените загрузку и перезагрузите устройство.
- `POST /api/ota/finish` — проверить целостность полностью переданного приложения, выбрать новый загрузочный раздел и перезагрузиться.
- `POST /api/ota/cancel` — отменить загрузку, сохранив блокировку движения.
- `POST /api/ota/reboot` — перезагрузить устройство после начала обновления.
- `POST /api/ota/arduino` — включить ArduinoOTA на 10 минут. Имя и временный пароль возвращаются последующим `GET /api/ota`.

Кроме `/write`, POST-запросы имеют пустое тело. Успех возвращает `{"ok":true}`, ошибка — JSON с `error`. Во время обновления обычные команды и изменение настроек через HTTP возвращают 503 `update_locked`.

## ArduinoOTA без браузера

Активация и получение временного пароля доступны через [командный API](../api/command-api.md#обновление-по-сети) в обычных сборках и профилях `esp32_4mb_noweb` и `wt32_eth01_noweb`.
