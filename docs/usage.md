# Использование

## Режимы

Первый запуск — ручной. Числовые внешние цели AZ, EL, AZ+EL и GS-232 последовательности сохраняются для подтверждения. Новая цель заменяет ожидающую, сохраняя текущий поворот. LEFT/RIGHT (L/R), UP/DOWN (U/D) на G-5500, STOP и запросы положения выполняются сразу через USB UART0, HC-05, TCP и UDP.

BOOT/GPIO0 или веб «Повернуть» запускает ожидающую цель. Дребезг 40 мс; удержание даёт одно событие, удержание при загрузке не запускает движение. GPIO0, удержанный до включения питания, аппаратно переводит ESP32 в загрузчик.

«Автоматический» сразу выполняет ожидающую и последующие цели. «Авто 1 ч» начинает новый час при каждом выборе; после 3600 секунд включается ручной, текущая точка завершается, последовательность дальше не идёт. Переход в ручной также позволяет закончить текущую точку. Направление отменяет наведение только соответствующей оси, сохраняя ожидающую цель. STOP очищает движение, ожидание и последовательность, сохраняя режим.

Постоянные ручной/автоматический сохраняются в NVS. «Авто 1 ч» после перезагрузки становится ручным. Цели не сохраняются и не воспроизводятся. Если цель не откалибрована, подтверждение не запускает её, а автоматический режим сохраняется с сообщением `target_not_calibrated`.

## Предустановки и профили

Четыре кнопки выполняются сразу в любом режиме. Имена и AZ/EL редактируются в вебе; начальные значения AZ 0/90/180/270, EL 0. Пресет очищает ожидание; до достижения цели внешние команды движения отбрасываются, включая направления. STOP и положение доступны. Второй пресет заменяет первый. Режим и часовой таймер сохраняются.

G-800DXA использует только AZ. Комбинированная команда с EL=0 допускается; ненулевой EL и U/D отклоняются. Веб и экран скрывают ось EL. Смена модели останавливает движение, очищает ожидание и выбирает ручной. Калибровки и пресеты раздельные: старый G-5500 NVS `g5500`, G-800DXA `g800cal`; пресеты `fork5500`/`fork800`, общие настройки `forkcfg`. P36/P45 и обе схемы калибровки сохранены.

## N1MM+

Имя ротатора по умолчанию `G5500`, UDP 12040; настраиваются в вебе. В N1MM Configurer → Broadcast Data → Rotor указать `IP_контроллера:12040`, а в Antennas использовать точно такое же Rotor Description. Включить Display Rotors Responding From Network. Промежуточный N1MMRotor.exe для прямого UDP не требуется.

Для прямого UDP вводите угол в поле позывного Logger+ и нажимайте Alt+J; Ctrl+Alt+J отправляет STOP. Выбирайте нужную антенну через Alt+F9: её Offset и Bidirectional влияют на итоговую цель. Кнопка Turn отдельной программы N1MM Rotor работает через настроенный COM-порт; один адрес UDP в Logger+ не создаёт такое соединение. В ручном режиме полученная цель появится как ожидающая. Для выполнения числовой цели нужна калибровка соответствующей оси.

Принимаются `N1MMRotor/rotor`, `goazi`, `offset`, `bidirectional`, `freqband`, `app`, а также вложенный `stop/rotor`. Имена в `rotor` могут перечисляться через запятую; `*` означает все ротаторы (реальный N1MM использует его при вводе числового азимута). Чужие имена и неверные пакеты не меняют состояние. `offset` добавляется к цели, bidirectional выбирает ближайшее из направлений, разнесённых на 180°. С учётом перекрытия выбирается ближайшее допустимое положение AZ; GS-232 M/W сохраняют механические градусы 0…450.

Фактическое положение `имя@азимут` отправляется раз в 500 мс на UDP 13010 IP-адресам, от которых пришли адресованные команды (до 8 компьютеров), и дополнительному Report IP из веба. Report IP помогает показывать положение до первой команды и после перезагрузки. Угол в UDP-отчёте передаётся в десятых долях градуса: `G5500@1370` означает 137°. Это проверено с N1MM Logger+ 1.0.11455; отправка `@137` даёт неверную индикацию 14°. Направление отчёта нормализуется к 0…359,9°, механическое положение в вебе 0…450.

[Официальный формат и настройка N1MM](https://n1mmwp.hamdocs.com/setup/interfacing/#rotator-udp-packet-information).

## UR5EQF / PST UDP

UDP 1234 по умолчанию, порт меняется в вебе. В UR5EQF выбрать UDP/PstRotator, указать IP контроллера и этот порт. Принимаются XML `<PST>…</PST>`: AZIMUTH, LEFT/RIGHT, STOPR/STOP, LP, информационные CALL/FREQUENCY/RADIO, TRACK (проверяется как 0/1, не меняет выбранный режим), ELEVATION для G-5500. LP выбирает длинный путь +180°. `PARK=1` из настоящего UR5EQF выбирает сохранённую цель пресета 1 как внешнюю числовую команду: в ручном она ждёт подтверждения, при активном пресете отбрасывается. `PARK=0` не запускает движение. Другие управляющие расширения PstRotator не реализованы.

`<PST>AZ?</PST>` возвращает `AZ:123.4\r`; TGA? возвращает ожидающий/исполняемый азимут. Ответ идёт IP отправителя на **настроенный порт приёма + 1**, независимо от исходящего порта клиента. STOP здесь сохраняет режим согласно правилам форка. [Протокол PstRotatorAz, стр. 11–12](https://pstrotator.com/ANT/PstRotatorAz%20User%20Manual.pdf).

## USB, Bluetooth, TCP

Сохранён USB через UART0 мост платы: 9600 baud, GS-232. Native Hardware CDC/JTAG используется для диагностики и программирования. HC-05 на UART1 — GS-232, штатные параметры оригинала. TCP 4533 сохраняет rotctld: `P az el`, `p`, `S`, `set_pos`, `get_pos`, `stop`, а также GS-232 L/R/U/D, M/W, X1…X4; строки CR, LF, CRLF. USB/HC-05/TCP принимают до 512 байт на строку; переполненная или содержащая недопустимые байты строка целиком отбрасывается до разделителя. Запросы калибровки и диагностики оригинала обрабатывает адаптер устройства.

## Веб API

Существующие GET-маршруты, калибровки, Wi-Fi, диагностика сохранены. Новые операции принимают `application/x-www-form-urlencoded`:

| Метод / путь | Поля |
|---|---|
| GET `/api/status` | оригинальные поля + model, controlMode, remainingMs, pendingValid/pending, presetActive/presetSlot, presets, speedEnabled/speedPercent, fault, сетевые настройки |
| POST `/api/mode` | mode=manual/auto/auto_1h |
| POST `/api/execute` | без полей |
| POST `/api/preset` | slot=1…4, label, az, el (G-5500) |
| POST `/api/preset/run` | slot=1…4 |
| POST `/api/settings` | model=G5500/G800DXA, rotorName, n1mmReport, n1mmPort, pstPort, reportPort, reportHost, speedEnabled=true/false, speedPercent=25…100 |
| POST `/api/target` | az, необязательный el; явная локальная команда выполняется сразу |

JSON: `ok`, `result`; 200 успешно/ожидание, 400 неверно/нет калибровки, 409 команда отложена приоритетом пресета. Оригинальная `/api/move?d=L/R/U/D/S/A/E` доступна для локального управления.
