# Покрытие возможностей оригинала и отличия форка

Оригинал: [UA1CFM/G5500-ESP32S3-Controller](https://github.com/ua1cfm/G5500-ESP32S3-Controller). Сопоставлены исходники и архивы v1.5.48–v1.6.29; снимок upstream `2862c5ba8c2e0712eb550ab168d6fca861bf3f8c`. База форка — v1.6.23 P36/P45 SAFE TCP COLOR. Варианты веток объединены выбором возможностей при сборке, без копирования скетча для каждого контроллера.

| Возможность / ветка оригинала | Реализация форка | Проверка |
|---|---|---|
| AZ/EL, аппаратные направления, GS-232 L/R/U/D/A/E/S, M/W, X1…X4 | control/protocol/hardware; X влияет только на AZ | native, TCP/UDP replay, обе системы сборки |
| GS-232 таймерная последовательность M/W + T, N=k/n | индекс активной точки, STOP → N=0/0 | core/drive tests |
| Двухточечные O/F/O2/F2, P36/P45 | calibration/application/storage; смена диапазона останавливает только AZ | native, сборка адаптера |
| MULTI и независимые AZ36/AZ45, флаги сохранённых точек (1.5.57/58+) | отдельные таблицы, прежние ключи и миграции calfmt 2/3/4 | типизированный NVS fake и математика |
| LCD1602 (1.5.48/54) | параллельный HD44780, позиции/цели/---, PWM, режим/ожидание | LCD-компиляции обеих плат; физический экран отдельно |
| Внешний HC-05 / STATE и GS-232 UART | условный UART1, без объекта/GPIO при OFF | варианты матрицы, GPIO-профили |
| Native USB диагностика, UART0 GS-232, TCP4533 rotctld/GS-232 | network/diagnostics; RX/TX по профилю платы | сетевые тесты/матрица |
| Веб, ADC-графики, калибровка и выбор P36/P45 | общий web_page/API/web_server | Chromium: desktop/mobile, режимы и калибровка |
| Диагностический лог, reset reason/history, NTP/время ПК, RSSI история | diagnostics/storage; сохранены существующие маршруты и ключи | сборки; живые NTP/NVS/радиоканал отдельно |
| Wi-Fi STA+AP, пароль AP, безопасное переподключение 30 с / 8 с | network без блокировки управления при повторных попытках | сборки; реальная связь отдельно |
| TFT ILI9341, XPT2046, touch-calibration/recovery, цвет TCP, картинка (1.6.23+) | display; полное исключение при NONE/LCD | TFT-матрица, прежние страницы/калибровки сохранены |
| PWM обеих осей, разгон/торможение, шкалы и live P36/P45 (1.6.29) | SEPARATE_PWM, общая логика обеих осей, раздельные настройки и шкалы TFT/LCD | fake GPIO/LEDC, все варианты сборки |

Форк сохраняет ручное подтверждение внешней числовой цели, Auto/AutoHour, четыре пресета с приоритетом, G-800DXA, прямые UDP N1MM/UR5EQF/5MContest и аналоговый каскад G-800DXA 20 кГц → 0…5 В. Новые возможности: S2 Mini, настраиваемая кнопка, выбор NONE/TFT/LCD и HC-05, интерфейс стандартных BTS7960, аппаратная конфигурация в status, раздельные параметры AZ/EL, схема SVG/PNG/PDF.

Отличия поведения зафиксированы явно:

- По умолчанию остановка в зоне ±5° с медианой пяти выборок по 20 мс поверх среднего 25 ADC-измерений. Пересечение цели завершает проход; обратной коррекции и прежнего продолжения вращения после цели нет.
- Повтор внешней цели в пределах допуска от последней принятой для оси не возобновляет движение; игнорируемые значения не сдвигают базу. Локальная команда может начать новый проход. Новая достаточно изменившаяся цель может выбрать противоположное направление.
- Замедление отсчитывается до границы зоны остановки. Все проценты описывают выход управления, а не измеренную скорость двигателя.
- STOP сохраняет режим, очищает ожидание/последовательность; пресеты сохраняют свой приоритет. Цели не восстанавливаются после перезапуска.
- YAESU и независимые PWM-приводы выбираются при сборке; настройки PWM не перезаписывают аналоговые настройки Yaesu. GPIO21/33/47 у BTS7960 являются ENABLE.
- Ошибка инициализации LEDC блокирует движение до перезапуска и сохраняется при смене модели; нет перехода на движение с неподтверждённым выходом скорости.

Z не реализован в исследованных оригинальных вариантах и не добавлялся. Встроенный Bluetooth/BLE, веб-OTA, GS-232 на native CDC вместо UART0 и дополнительные расширения PstRotator не заявляются. LCD/TFT, питание, реальные PWM и механика требуют отдельной проверки; успешная сборка не является доказательством работы оборудования.

Компоненты владеют своим состоянием: control/protocol/input/api/calibration — переносимое ядро; board/build_config — аппаратные профили; hardware/storage/diagnostics/network/web_server/display — адаптеры. Единственный Runtime связывает контроллер с интерфейсами. Arduino и PlatformIO компилируют одни и те же соседние файлы скетча.
