# MQTT и Home Assistant

[Документация](../index.md) · [Внешние программы](index.md)

## Подключение

1. Подключите контроллер или HUD к сети с MQTT-брокером. В Home Assistant добавьте интеграцию [MQTT](https://www.home-assistant.io/integrations/mqtt/) и укажите свой брокер.
2. В веб-интерфейсе устройства откройте **Настройки → Настройки сети → MQTT и Home Assistant**.
3. Введите адрес брокера, TCP-порт (обычно `1883`), логин и пароль. Подключение использует TCP без TLS. По умолчанию MQTT выключен.
4. Включите подключение и автообнаружение Home Assistant. Префикс discovery должен совпадать с настройкой HA; по умолчанию это `homeassistant`.
5. Сохраните настройки. Устройство остановит движение и перезапустится. Статус подключения доступен в той же форме и через `GET /api/mqtt`.

Пустое поле пароля в форме сохраняет прежний пароль. Для удаления используйте отдельный переключатель. Пароль никогда не возвращается через API. Если подключение не запускается из-за недостатка памяти, статус содержит `mqtt_memory_limited`: выберите сборку с меньшим набором [функций](../setup/configuration.md#отключение-функций).

## Устройства в Home Assistant

Контроллер создаёт устройство своей поворотки. HUD создаёт отдельное устройство для каждой сохранённой поворотки каталога, а также устройство **«Текущая выбранная поворотка»**. Последнее управляет выбором, показанным на экране HUD. Команда, ожидавшая выполнения при смене выбора, отклоняется с `selection_changed`.

Адресные команды отдельной поворотки используют её сохранённый Wi-Fi, UART или RS‑485/Modbus адрес и сохраняют выбор на экране. Доступность каждой поворотки определяется свежестью её собственных данных; потеря связи с одной не отключает остальные.

В зависимости от модели и привода доступны:

- положение AZ/EL, движение, ошибка и признак ожидающей цели;
- цели AZ/EL и режим `manual`, `auto`, `auto_1h`;
- рабочая скорость каждой оси; единицы — проценты или °/с для каскадного регулятора;
- общий STOP, отдельные STOP AZ/EL, подтверждение цели и четыре сохранённых пресета;
- имя и идентификатор текущего источника данных.

В ручном режиме числовая цель ожидает подтверждения; число в поле цели показывает ожидаемое значение. В автоматических режимах цель выполняется сразу. Требования к калибровке, ограничения движения и защиты действуют также для MQTT.

Discovery сохраняется в брокере и публикуется повторно после сообщения `online` в `<префикс>/status`. При удалении записи каталога HUD удаляет её discovery-конфигурации. При смене префикса старые конфигурации удаляются после подключения к тому же брокеру. Для очистки при выключении discovery оставьте само MQTT-подключение включённым до завершения удаления. При смене брокера старые retained-записи остаются в прежнем брокере; удалите их там отдельно.

## Темы MQTT

Идентификатор шлюза и поворотки — 12 шестнадцатеричных цифр без разделителей. На контроллере они совпадают. Их можно увидеть в `GET /api/mqtt`, `/api/device` и каталоге HUD.

| Тема | Содержимое |
|---|---|
| `g5500/<шлюз>/availability` | `online` / `offline`, retained, LWT |
| `g5500/<шлюз>/<поворотка>/state` | JSON, retained |
| `g5500/<шлюз>/selected/state` | JSON текущего выбора HUD, retained |
| `g5500/<шлюз>/<поворотка>/set/<команда>` | Команда, **без retain**, QoS 0 |
| `g5500/<шлюз>/selected/set/<команда>` | Команда текущего выбора HUD, **без retain**, QoS 0 |

| Команда | Payload |
|---|---|
| `target_az`, `target_el` | Число в градусах механического диапазона |
| `speed_az`, `speed_el` | Число в единицах текущего регулятора |
| `mode` | `manual`, `auto`, `auto_1h` |
| `stop`, `stop_az`, `stop_el` | `PRESS` |
| `execute` | `PRESS` |
| `preset_1` … `preset_4` | `PRESS` |

В `state` находятся `available`, `name`, `node`, `mode`, `fault`, `pending`, `moving`, а также объекты `az` и `el`: `current`, `target`, `pending`, `speed`, `adjustable`. Неизвестные и неподдерживаемые координаты передаются как `null`. `target` отражает ожидающую цель, если она есть, иначе текущую цель движения; `az.pending` / `el.pending` содержат только отложенные значения.

Очередь команд ограничена; STOP имеет отдельные места и отменяет более ранние числовые команды тому же адресату. Команды старше двух секунд и команды предыдущего подключения отбрасываются. После восстановления связи управление возобновляйте свежей командой. Поля `rejected`, `dropped`, `lastResult` и `requestId` в `/api/mqtt` помогают диагностировать отказ или ожидание подтверждения HUD.

## HTTP и командный API

`GET /api/mqtt` возвращает `enabled`, `host`, `port`, `username`, `hasPassword`, `discovery`, `discoveryPrefix`, `storageOk`, `supported`, `connected`, `error` и диагностику активного клиента. Поля `password` в ответе нет.

`POST /api/mqtt` принимает форму `application/x-www-form-urlencoded`:

```text
enabled=1&host=192.168.1.10&port=1883&username=radio&discovery=1&discoveryPrefix=homeassistant
```

Поля необязательны: пропущенное значение сохраняется. `enabled` и `discovery` принимают `0`/`1` или `false`/`true`. `password=` удаляет пароль, отсутствие `password` сохраняет его. При успехе возвращается `{"ok":true,"restart":true}`; для неизменённой конфигурации `restart` равен `false`. Неверные поля дают HTTP 400, ошибка записи — 503 и `mqtt_storage_failed`, исключённая функция — 501 и `feature_disabled`.

Те же GET/POST доступны через [командный API](../api/command-api.md). Возможности конкретной сборки перечислены в `build.features` полного HTTP-ответа `/api/status` и ответа `/api/config` (HTTP и командный API).
