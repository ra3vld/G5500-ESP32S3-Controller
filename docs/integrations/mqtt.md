# MQTT и Home Assistant

## Подключение

Для обычного ESP32 WROOM/WROVER используйте `pio run -e esp32_4mb`: его стандартный набор функций освобождает RAM для TLS. `esp32_4mb_mqtt_tls` сохранён как алиас этой сборки. Используются компактные буферы Wi-Fi. Он сохраняет веб-интерфейс с HTTP-опросом, внешний HC-05, командный API и управление приводом; встроенный SPP, сервер WebSocket, история логов и RSSI, а также OTA исключены. Обновление выполняется через USB; разметка остаётся с одним приложением 3 МиБ. Если сохранённые настройки включали встроенный SPP, сначала выключите его в настройках оборудования. Для обычного ESP32 с 4 МиБ Flash и OTA доступен `esp32_4mb_ota_compact`. В [сборке S2 без PSRAM](../build.md#esp32-s2-без-psram) прямой MQTT отключён для сохранения внутренней памяти. Подключите такой контроллер по UDP к HUD с MQTT и управляйте им через MQTT-темы HUD.

1. Подключите контроллер или HUD к сети с MQTT-брокером. В Home Assistant добавьте интеграцию [MQTT](https://www.home-assistant.io/integrations/mqtt/) и укажите свой брокер.
2. В веб-интерфейсе устройства откройте **Настройки → Настройки сети → MQTT и Home Assistant**.
3. Введите адрес брокера, TCP-порт (обычно `1883`), логин и пароль. Для шифрованного подключения включите **Шифрование TLS** и укажите порт брокера (обычно `8883`). По умолчанию MQTT и TLS выключены.
4. Включите подключение и автообнаружение Home Assistant. Префикс discovery должен совпадать с настройкой HA; по умолчанию это `homeassistant`.
5. Сохраните настройки. Устройство остановит движение и переподключит MQTT без перезагрузки. Статус MQTT виден на главной странице, в блоке **Настройки → Статус сети** и через `GET /api/mqtt`. При ошибке подключения веб-интерфейс показывает её причину.

Пустое поле пароля в форме сохраняет прежний пароль. Для удаления используйте отдельный переключатель. Пароль никогда не возвращается через API. Если подключение не запускается из-за недостатка памяти, статус содержит `mqtt_memory_limited`: выберите сборку с меньшим набором [функций](../setup/configuration.md#отключение-функций).

### TLS и память

Для TLS укажите DNS-имя, совпадающее с сертификатом брокера. Устройство проверяет имя, срок действия и цепочку сертификата через встроенные доверенные центры сертификации. Самоподписанные сертификаты, пользовательские CA и клиентские сертификаты не поддерживаются. Обеспечьте доступ к NTP для установки времени; при неверном времени соединение ждёт с `mqtt_tls_time_required`.

TLS использует существующее MQTT-подключение. При выключенном MQTT клиент, его задачи, очереди и TLS-контекст не создаются; выключение работающего MQTT освобождает их без перезагрузки. Выключение только TLS переключает MQTT на обычный TCP, поэтому проверьте порт. Сертификаты доверенных центров находятся во Flash.

Перед TLS-подключением проверяется запас внутренней RAM: не менее 96 КиБ свободно и крупный непрерывный блок (не менее 32 КиБ, либо больше в зависимости от размера клиента). Это защитный порог, а не гарантированный расход TLS. При нехватке памяти отображается `mqtt_tls_memory_limited`; клиент ждёт освобождения памяти. После потери TLS-связи клиент освобождается, следующая попытка выполняется не раньше чем через 10 секунд с повторной проверкой памяти и остановки движения. Автоматического перехода на незашифрованное подключение нет.

В режиме восстановления MQTT и TLS не запускаются независимо от сохранённых настроек. На странице **Восстановление** нажмите **Отключить MQTT и TLS**, чтобы сохранить отключение также для обычного запуска. Адрес и учётные данные брокера сохранятся. Настройки MQTT доступны через API и в recovery.

Поддержку TLS можно исключить при сборке флагом `MQTT_TLS_SUPPORT=0`. Обычный MQTT останется доступен. Возможность TLS указана в `build.features.mqttTls`.

## Устройства в Home Assistant

MQTT также поддерживает прямую связь **HUD ↔ контроллер через брокер**. Настройка описана в [руководстве HUD](../control/hud.md#через-mqtt). **Для связи HUD с контроллером рекомендуется UDP; используйте MQTT только когда подключение по UDP невозможно.** Она использует то же MQTT-подключение и работает независимо от включения discovery Home Assistant.

Контроллер создаёт устройство своей поворотки. HUD создаёт отдельное устройство для каждой сохранённой поворотки каталога, а также устройство **«Текущая выбранная поворотка»**. Последнее управляет выбором, показанным на экране HUD. Команда, ожидавшая выполнения при смене выбора, отклоняется с `selection_changed`.

Адресные команды отдельной поворотки используют её сохранённый Wi-Fi, UART, RS‑485/Modbus адрес или MQTT-транспорт и сохраняют выбор на экране. Доступность каждой поворотки определяется свежестью её собственных данных; потеря связи с одной не отключает остальные.

В зависимости от модели и привода доступны:

- положение AZ/EL, движение, ошибка и признак ожидающей цели;
- цели AZ/EL и режим `manual`, `auto`, `auto_1h`;
- рабочая скорость каждой оси; единицы — проценты или °/с для каскадного регулятора;
- общий STOP, отдельные STOP AZ/EL, подтверждение цели и четыре сохранённых пресета;
- переключатели **Влево** и **Вправо**, а у моделей с элевацией — **Вверх** и **Вниз**;
- имя и идентификатор текущего источника данных.

В ручном режиме числовая цель ожидает подтверждения; число в поле цели показывает ожидаемое значение. В автоматических режимах цель выполняется сразу. Требования к калибровке, ограничения движения и защиты действуют также для MQTT.

Включение переключателя направления сразу запускает движение выбранной оси в любом режиме. Повторное нажатие выключает переключатель и останавливает только эту ось. Включение противоположного направления меняет направление через штатную обработку реверса. Общий STOP и STOP соответствующей оси также доступны; ограничения диапазона и защиты действуют штатным образом.

Состояние переключателей приходит от контроллера и отражает заданное направление оси, в том числе при управлении с другого пульта или наведении на цель. После остановки оба переключателя оси выключены. При обновлении прошивки старые кнопки направлений удаляются из автообнаружения и заменяются переключателями. Если кнопки были добавлены на панель HA вручную, замените их новыми сущностями `switch`.

Discovery сохраняется в брокере и публикуется повторно после сообщения `online` в `<префикс>/status`. При удалении записи каталога HUD удаляет её discovery-конфигурации. При смене префикса старые конфигурации удаляются после подключения к тому же брокеру. Для очистки при выключении discovery оставьте само MQTT-подключение включённым до завершения удаления. При смене брокера старые retained-записи остаются в прежнем брокере; удалите их там отдельно.

## Темы MQTT

Идентификатор шлюза и поворотки — 12 шестнадцатеричных цифр без разделителей. На контроллере они совпадают; у HUD идентификатор шлюза относится к пульту, идентификатор поворотки — к записи его каталога. В веб-интерфейсе ID устройства показан в **Настройки → Статус сети** и **Настройки → Настройки сети → MQTT и Home Assistant**, в том числе при выключенном MQTT. Нажмите на поле в настройках MQTT, чтобы выделить ID для копирования. ID также доступен в `/api/device` и каталоге HUD.

| Тема | Содержимое |
|---|---|
| `g5500/<шлюз>/availability` | `online` / `offline`, retained, LWT |
| `g5500/<шлюз>/<поворотка>/state` | JSON, retained |
| `g5500/<шлюз>/selected/state` | JSON текущего выбора HUD, retained |
| `g5500/<шлюз>/<поворотка>/config` | Возможности и диапазоны поворотки, JSON, retained |
| `g5500/<шлюз>/selected/config` | Возможности текущего выбора HUD, JSON, retained |
| `g5500/<шлюз>/<поворотка>/set/<команда>` | Команда, **без retain**, QoS 0 |
| `g5500/<шлюз>/selected/set/<команда>` | Команда текущего выбора HUD, **без retain**, QoS 0 |

| Команда | Payload |
|---|---|
| `target_az`, `target_el` | Число в градусах механического диапазона; в ручном режиме ожидает подтверждения |
| `move_az`, `move_el` | Число в градусах механического диапазона; выполняется сразу, сохраняя режим |
| `speed_az`, `speed_el` | Число в единицах текущего регулятора |
| `mode` | `manual`, `auto`, `auto_1h` |
| `stop`, `stop_az`, `stop_el` | `PRESS` |
| `left`, `right` | `ON`: движение AZ влево / вправо; `OFF`: STOP AZ. Прежний `PRESS` также запускает движение |
| `up`, `down` | `ON`: движение EL вверх / вниз; `OFF`: STOP EL, только у моделей с элевацией. Прежний `PRESS` также запускает движение |
| `execute` | `PRESS` |
| `preset_1` … `preset_4` | `PRESS` |

В `state` находятся `available`, `name`, `node`, `mode`, `fault`, `pending`, `moving`, а также объекты `az` и `el`: `current`, `target`, `pending`, `speed`, `adjustable`, `direction`. Неизвестные и неподдерживаемые координаты передаются как `null`. `target` отражает ожидающую цель, если она есть, иначе текущую цель движения; `az.pending` / `el.pending` содержат только отложенные значения. `direction` — заданное контроллером направление: `-1` влево / вниз, `1` вправо / вверх, `0` остановка. При паузе реверса заданное направление может уже измениться, пока выход привода выключен.

В `config` находятся `version=1`, `node`, `axes` (`az` или `az_el`), границы `az.min` / `az.max` и `el.min` / `el.max` (без EL — `null`), `speed` с полями `max`, `unit` (`%` или `deg/s`) и `adjustable` для AZ, четыре имени `presets` и признак `direct_target`. Конфигурация публикуется после подключения и при изменении её параметров; у `selected/config` она относится к текущему выбору HUD. Это отдельные темы от discovery Home Assistant.

`move_az` / `move_el` подходят для кнопок немедленного наведения в собственном клиенте. Они действуют как ввод цели в веб-интерфейсе: не требуют ручного подтверждения, но сохраняют проверки калибровки, диапазона и защит привода. Обычные `target_az` / `target_el`, в том числе поля цели Home Assistant, следуют режиму управления.

Очередь команд ограничена; STOP имеет отдельные места и отменяет более ранние команды движения тому же адресату. Команды старше двух секунд и команды предыдущего подключения отбрасываются. После восстановления связи управление возобновляйте свежей командой. Поля `rejected`, `dropped`, `lastResult` и `requestId` в `/api/mqtt` помогают диагностировать отказ или ожидание подтверждения HUD.

Для связи HUD используются отдельные темы `g5500/hud/<ID получателя>/rx` и `g5500/hud/discover`. Они передают бинарные кадры HUD/1 с QoS 0 без retain. Не записывайте retained-команды в эти темы. При использовании ACL разрешите каждому устройству подписку на свою тему приёма и публикацию в темы адресатов; контроллерам также нужна подписка на `g5500/hud/discover`.

## HTTP и командный API

`GET /api/mqtt` возвращает `enabled`, `host`, `port`, `username`, `hasPassword`, `tls`, `tlsSupported`, `discovery`, `discoveryPrefix`, `storageOk`, `supported`, `connected`, `error` и диагностику активного клиента. Поля `password` в ответе нет.

`outboxBytes` показывает последний измеренный размер очереди MQTT, а `outboxAgeMs` — возраст этого измерения. `stackFreeBytes` и `publishStackFreeBytes` показывают минимальный свободный стек клиента и передатчика. `disconnects` считает отключения брокера, `tcpRetired` — освобождённые завершённые TCP-соединения, `tcpMssLimit` — применённый верхний предел TCP-сегмента. При перегрузке отправка ограничивается; команды управления продолжают обрабатываться независимо от ожидания сетевой отправки.

`clientAllocated` показывает наличие клиента и его буферов. `tlsError` и `tlsVerifyFlags` содержат код TLS и флаги ошибки проверки сертификата, в том числе во время ожидания повторного подключения. `brokerError` сохраняет код отказа брокера после освобождения клиента: `4` — неверные учётные данные, `5` — доступ не разрешён.

Завершение соединения выполняется асинхронно. После отключения MQTT или смены настроек `connected=false`, а `stopping=true` и `error="stopping"` означают, что прежнее соединение ещё освобождает ресурсы. Дождитесь `clientAllocated=false`, прежде чем оценивать освобождённую память. `stopMaxUs` показывает максимальную длительность завершения; новый клиент запускается после освобождения прежнего.

Поля `hudRxFrames` и `hudTxFrames` считают кадры связи HUD через брокер, `hudDropped` — сообщения, не принятые адаптером или его ограниченной очередью, `hudThrottled` — пропущенные избыточные запросы состояния, `hudControlDeferred` — отложенные запросы перед наступающим шагом регулятора. `hudBufferBytes` показывает объём фиксированных буферов этого транспорта, `hudServiceMaxUs` — наибольшее измеренное время обработки входящих кадров в основном цикле. `hudPublishMaxUs` измеряет наибольшую длительность отправки кадра отдельной задачей, `hudPublishFailures` считает её ошибки. `hudSocketReady=true` подтверждает отключение Nagle и применение IP precedence 4 для MQTT-соединения; действие приоритета за пределами устройства зависит от сети. `transportErrorType`, `socketError` и `transportError` содержат последние коды ошибки транспорта SDK и сокета.

HTTP `GET /api/status` содержит краткий объект `mqtt`: `enabled`, `storageOk`, `supported`, `connected`, `error` и, после запуска клиента, `brokerError`. Настройки применяются после сохранения без перезагрузки. Учётные данные и подробные счётчики в краткий статус не входят. В сборке без MQTT объект содержит `supported=false` и `error="feature_disabled"`.

`POST /api/mqtt` принимает форму `application/x-www-form-urlencoded`:

```text
enabled=1&host=192.168.1.10&port=1883&username=radio&discovery=1&discoveryPrefix=homeassistant
```

Поля необязательны: пропущенное значение сохраняется. `enabled`, `tls` и `discovery` принимают `0`/`1` или `false`/`true`. `password=` удаляет пароль, отсутствие `password` сохраняет его. При успехе возвращается `{"ok":true,"restart":false}`. Изменения применяются только после проверенной записи настроек; действующий клиент сначала освобождается, затем запускается с новыми параметрами. Неверные поля дают HTTP 400, ошибка записи — 503 и `mqtt_storage_failed`, исключённая функция — 501 и `feature_disabled`.

Те же GET/POST доступны через [командный API](../api/command-api.md). GET через командный API возвращает настройки и компактный статус клиента; подробные быстро меняющиеся счётчики доступны по HTTP. Возможности конкретной сборки перечислены в `build.features` полного HTTP-ответа `/api/status` и ответа `/api/config` (HTTP и командный API).
