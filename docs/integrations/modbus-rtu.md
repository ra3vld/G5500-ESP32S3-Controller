# Modbus RTU и общая линия с маркером

[Документация](../index.md) · [Подключение RS‑485](rs485.md)

Прошивка поддерживает обычные запросы Modbus RTU и режим общей линии, в котором несколько HUD и шлюз ПК по очереди получают право начать запрос. Устройства Modbus, отвечающие на запросы, используют стандартные кадры. Передача маркера между ведущими — расширение прошивки на пользовательской функции `0x41`.

## Подключение и настройка

```text
ПК — USB–RS‑485 — UART0 HUD №1 — UART1 ─┬─ UART1 контроллера
                                      ├─ UART1 контроллера №2
                                      ├─ UART1 HUD №2
                                      └─ другие ведомые Modbus RTU
```

Линия компьютера и общая линия электрически независимы. На HUD с компьютером нужны два UART и два трансивера. Другим HUD и контроллерам достаточно одного трансивера UART1. RX/TX/DE назначаются на свободные GPIO; требования к уровню 3,3 В, DE/RE, согласованию и кабелю приведены в [инструкции RS‑485](rs485.md#кабель-и-проверка). UART1 нельзя одновременно использовать для HC‑05.

1. На странице `/hardware` назначьте RX/TX/DE нужных портов, сохраните и подтвердите оборудование.
2. В настройках роли выберите контроллер или HUD и включите **HUD UART** на всех устройствах общей линии.
3. В разделе **UART и RS‑485** выберите для UART1 **Modbus RTU с маркером** и задайте одинаковые параметры линии на всех участниках, например **115200, 8E1**.
4. На каждом контроллере задайте его собственный уникальный **адрес контроллера** `1…247` вне диапазона ведущих. Например, `1`, `2`, `3`. На HUD получатель определяется выбранной записью в каталоге повороток; поле адреса используется только для старых записей UART без адреса.
5. Задайте одинаковые **первый адрес ведущих** и **число ведущих** на всех устройствах. Поддерживается от одного до четырёх ведущих, включая HUD и шлюз ПК, занимающих последовательные адреса. Например, для двух HUD: первый `201`, число `2`, служебные адреса HUD `201` и `202`. На контроллере служебный адрес не участвует в передаче маркера; оставьте любое значение внутри этого диапазона.
6. Сохраните протоколы и дождитесь перезапуска. На HUD откройте **Настройки → Поворотки**, задайте диапазон адресов и нажмите **Найти на шине RS‑485**. Контроллеры опрашиваются последовательно, адреса ведущих пропускаются. Нажмите найденную поворотку, чтобы сохранить её; повторите для остальных. Выбирайте получателя в общем списке HUD, в том числе на его экране. Адрес сохраняется вместе с записью.

Поиск запускается по запросу. Для небольшого числа контроллеров сузьте диапазон до их адресов: ожидание отсутствующего устройства занимает около секунды, полный диапазон может потребовать нескольких минут. Текущий адрес показан рядом со счётчиком найденных устройств. Повторный поиск обновляет адрес записи с тем же ID. Обычные сторонние ведомые Modbus в каталоге повороток не отображаются.

На порту ПК можно оставить **GS‑232** с параметрами UART0 **9600, 8N1**: программа слежения продолжит работать через COM-порт без дополнительного ПО. Для обычного Modbus-клиента выберите **Modbus RTU**, отдельно задайте параметры UART0 и клиента, например **19200, 8E1**, отключите управление потоком и установите таймаут ответа не менее **2 секунд**. На медленной общей линии увеличьте таймаут с учётом времени передачи и числа участников кольца. Передавайте следующий запрос после ответа или истечения таймаута. HUD перенаправляет запрос на общую линию, когда получает маркер.

Modbus UART0 также работает непосредственно на контроллере, без HUD и без общей линии. Назначьте RX/TX/DE UART0 и выберите Modbus для порта ПК; HUD UART можно отключить.

## Шлюз на компьютере

Для прямого подключения ПК к общей шине используйте `tools/rs485_gateway.py`. Нужны Python 3.10 или новее и USB–RS‑485 с автоматическим переключением направления, без локального эха. Шлюз работает на Linux и Windows, участвует в MTR/1 и предоставляет GS‑232 по TCP одной программе управления. Дополнительный HUD между ПК и шиной не нужен.

```text
ПК — USB–RS‑485 ─┬─ контроллер №1 (адрес 1)
                 ├─ контроллер №2 (адрес 2)
                 └─ HUD (ведущий 201)
ПК: шлюз MTR/1, ведущий 202
```

1. На всех устройствах задайте одинаковое кольцо: первый адрес `201`, число ведущих `2`. HUD назначьте `201`, шлюзу — `202`. Каждый следующий ведущий занимает свой адрес внутри общего диапазона; максимум четыре, включая ПК.
2. Подключите адаптер к общей паре A/B и общему проводу согласно [правилам подключения](rs485.md#кабель-и-проверка).
3. Установите зависимость командой `python -m pip install pyserial` (на Linux вместо `python` может использоваться `python3`). Параметры последовательного порта поддерживаются [pySerial](https://pyserial.readthedocs.io/en/stable/pyserial_api.html).
4. Из каталога проекта запустите шлюз с параметрами вашей шины. Пример для Linux:

```sh
python3 tools/rs485_gateway.py --serial /dev/ttyUSB0 --node 202 --first 201 --count 2 --controller 1 --baud 115200 --parity E --stops 1
```

На Windows:

```powershell
python tools/rs485_gateway.py --serial COM5 --node 202 --first 201 --count 2 --controller 1 --baud 115200 --parity E --stops 1
```

5. В программе управления, например PstRotator, выберите GS‑232 через TCP: адрес `127.0.0.1`, порт `4533`. Шлюз поддерживает `C`, `C2`, `B`, `M<AZ>`, `W<AZ> <EL>` и `S`. Числовые команды выполняются с обычными правилами режима и подтверждения цели контроллера. Для слежения используйте автоматический режим. Неподдерживаемая команда или ошибка возвращает `?>`; при таймауте проверьте состояние перед повторной командой.

Получатель задаётся параметром `--controller`; для выбора другой поворотки завершите шлюз через Ctrl+C и запустите с её адресом. Команды ПК не меняют выбор на HUD. Параметр `--port` меняет TCP-порт, `--timeout` — срок ожидания запроса (по умолчанию 5 секунд). При медленной шине увеличьте срок с учётом скорости и числа ведущих. Для подключения с другого компьютера задайте `--host` с адресом сетевого интерфейса ПК; по умолчанию слушается только localhost.

Шлюз передаёт запросы лишь при наличии маркера, отдаёт его после ответа или таймаута и прекращает передачу при несовпадении параметров кольца. ОС и USB-адаптер влияют на задержки: остановка процесса более чем на 40 мс приводит к отказу от текущего маркера и ожиданию восстановления. Обмен с выключенным силовым питанием, доставку STOP и работу нескольких ведущих проверьте на своей линии перед управлением приводом.

## Совместимость и ограничения

- К общей линии можно подключить [шлюз ПК](#шлюз-на-компьютере) непосредственно через USB–RS‑485. На общей линии все ведущие должны поддерживать описанное расширение и иметь уникальные служебные адреса. Обычный Modbus-мастер подключается к отдельному UART0 HUD. Произвольный мастер на общей линии не участвует в арбитраже и может вызвать коллизии.
- Параметры общей линии задаются отдельно для UART1 и сохраняются при смене протокола. Сторонние ведомые должны использовать те же скорость, чётность и стоп-биты и иметь уникальные адреса вне диапазона ведущих.
- Шлюз пропускает функции `03`, `04`, `06`, `10`. Широковещательные запросы с адресом `0`, служебные адреса кольца и функция `0x41` с порта ПК не перенаправляются. Сам контроллер принимает только адресованные запросы.
- На общей линии допускается один незавершённый запрос. Таймаут всей транзакции от начала отправки — **80 мс** при 115200 бод; на медленной линии он увеличивается до времени передачи 512 символов выбранного формата плюс 20 мс. Ведомые должны укладываться в него с учётом времени передачи запроса и ответа; поздний ответ может нарушить обмен. Контроллер пропускает запросы при длительной задержке обработки, чтобы не отвечать после этого срока.
- Запросы ПК чередуются с обменом самого HUD, поэтому непрерывный опрос с компьютера не блокирует обновление пульта. После завершения обмена HUD передаёт маркер следующему доступному участнику. Отключённые участники пропускаются. После потери маркера восстановление начинается после секунды тишины; запуск и восстановление временно увеличивают задержку.
- Число HUD, длина ответов и ошибки линии увеличивают задержку. Непрерывное ручное управление использует ограниченные сроки действия команд; при недостаточной скорости обновления движение прекращается. Для плавного ручного управления предпочтительно небольшое кольцо.
- Передача маркера предполагает общую исправную линию, на которой участники слышат друг друга. Одинаковые адреса, разные настройки кольца, обрыв или соединение работающих сегментов могут нарушить арбитраж. После исправления адресов и проводки перезапустите участников.
- Уже принятая числовая цель может выполняться автономно после потери связи. Удерживаемое ручное управление прекращается при истечении его срока действия.

## Регистры контроллера

Номера функций в этом руководстве записаны в шестнадцатеричном виде. Номера регистров без префикса `0x` — десятичные.

Номера ниже — **нулевые адреса в PDU**, без прибавления `40001`. Чтение — функции `03` и `04`; диапазон `0…63`. 32-битные значения занимают два последовательных регистра, старшее слово первым. Углы — знаковые 32-битные числа в тысячных градуса, в механических координатах настроенного диапазона. Неиспользуемые регистры возвращают ноль.

| Регистры | Значение |
| --- | --- |
| 0 | Версия карты: `1` |
| 1 | Флаги: `1` AZ откалиброван, `2` EL откалиброван, `4` AZ запрошено движение, `8` EL запрошено движение, `16` ошибка привода, `32` управление доступно |
| 2 | Режим: `0` ручной, `1` автоматический, `2` автоматический на один час |
| 3 | Модель: `0` G5500, `1` G800DXA |
| 4–5, 6–7 | Текущие AZ, EL |
| 8–9, 10–11 | Целевые AZ, EL |
| 12–13, 14–15 | Начало и конец диапазона AZ |
| 16–17, 18–19 | Начало и конец диапазона EL |
| 20–21 | Счётчик STOP |
| 22–23 | ID последней команды блока записи |
| 24 | Результат: `0` принято, `1` ожидает подтверждения цели, `2` проигнорировано, `3` неверные данные, `4` нет калибровки, `5` ожидается ответ удалённого контроллера, `6` недоступно, `7` занято, `8` таймаут, `9` отменено |
| 26–27 | Время контроллера, миллисекунды, `uint32` |
| 28–29 | Идентификатор текущего запуска контроллера, `uint32` |
| 30–31 | Ревизия диапазонов |

Функция `06`, регистр **`0x110`**, значение **`1`** — немедленный STOP. Повторная отправка безопасна. Другие значения и адреса одиночной записи отклоняются.

Цели и остальные команды записываются **одним запросом функции `10`**: начальный адрес **`0x100`**, ровно **16 регистров / 32 байта**. Частичная запись блока запрещена, обе координаты проверяются до выполнения команды.

| Смещение регистра в блоке | Значение |
| --- | --- |
| 0 | Ненулевой ID источника, `uint16` |
| 1–2 | Ненулевой ID сеанса клиента, `uint32` |
| 3–4 | Ненулевой возрастающий ID команды, `uint32` |
| 5–6 | Идентификатор запуска из регистров `28–29` |
| 7–8 | Недавно прочитанное время контроллера из `26–27` |
| 9 | Код операции |
| 10 | Маска осей: `1` AZ, `2` EL, `3` обе |
| 11–12 | AZ, `int32` |
| 13–14 | EL, `int32` |
| 15 | Аргумент операции |

Коды операций: `1` задать цель, `2` STOP, `3` выполнить ожидающую цель, `4` выбрать режим (аргумент `0…2`), `5` вызвать пресет (аргумент `0…3`), `6` ручное управление. Для операции `6` координаты задают нормированное воздействие `−1000…1000`, аргумент `0` означает удержание, `1` — отпускание; отправляйте свежие команды регулярно. Остальные операции используют углы в тысячных градуса. В неиспользуемых полях передавайте нули.

Перед записью прочитайте время и идентификатор запуска. Время в команде должно быть не старше **2 секунд**; после перезапуска прочитайте новые значения. При повторе запроса используйте тот же ID и неизменный блок: команда не выполняется второй раз. Для новой команды увеличивайте ID; при новом сеансе создавайте новый ненулевой ID сеанса. Одновременно поддерживается восемь недавних сеансов записи.

Запись подчиняется обычным правилам режимов и подтверждения цели. Успешный ответ Modbus подтверждает приём команды; на HUD результат удалённой команды может ещё ожидаться. Читайте регистры состояния и результата. Исключения: `01` неподдерживаемая функция, `02` адрес регистра, `03` данные/срок действия/повтор с изменённым содержимым, `04` недоступность управления или калибровки, `06` занято. Шлюз возвращает `0B`, если ответ общей линии недоступен.

## Служебная функция 0x41

Обычным программам Modbus эти кадры формировать не требуется. Для совместимого ведущего формат RTU остаётся стандартным: адрес, `0x41`, длина тела одним байтом, тело, CRC16 Modbus (младший байт CRC первым). Все многобайтные поля тела — big endian. Кадр не длиннее 256 байт.

Кадры маркера имеют тело длиной 17 байт:

| Байты тела | Значение |
| --- | --- |
| 0 | Операция: `01` probe, `02` claim, `03` grant, `81` probe ACK, `83` grant ACK |
| 1, 2 | Адрес передающего владельца и адрес получателя маркера |
| 3, 4 | Первый адрес кольца, число участников |
| 5–8 | Номер эпохи восстановления, `uint32` |
| 9–12 | Номер передачи маркера, `uint32` |
| 13–14 | Срок владения в мс: максимум из 300 мс и трёх тайм-аутов транзакции |
| 15–16 | Сигнатура `0x4D54` |

Внешний адрес кадра равен адресу получателя маркера. В ACK тело запроса сохраняется, меняется только операция. Ответ `probe ACK` разрешает прежнему владельцу выдать `grant`. Он отказывается от права передачи **до** отправки `grant` и не возобновляет обмен при потере ACK. Получатель отвечает `grant ACK`, выдерживает тишину и начинает обмен; прежний владелец остаётся без маркера. Старая или повторная выдача маркера не принимается. Начинать новую транзакцию можно лишь с запасом не менее одного тайм-аута транзакции до окончания срока владения. После задержки обслуживания более 40 мс ведущий отказывается от своего маркера.

Восстановление: после тишины длительностью не менее 1000 мс и не менее трёх сроков владения первый участник может послать `claim`; следующие получают окна через 50 мс в порядке адресов. Окно длится 20 мс; пропущенное окно нельзя использовать позднее. Инициатор выбирает новую эпоху. После полной тишины принимается и эпоха перезапустившегося участника с меньшим числом: прежние сроки владения и допустимое время хранения кадров уже истекли. Только выигравший участник начинает запросы. Другая конфигурация кольца в служебном кадре блокирует участие до перезапуска.

Встроенный HUD использует операции `10` (обмен) и `90` (ответ) той же функции для фрагментов своего протокола. Адрес запроса — адрес контроллера, источник — служебный адрес HUD. Тело начинается с операции и адреса источника; далее `uint32` сеанса HUD. Оставшиеся поля запроса: ID передаваемого сообщения `uint32`, полный размер `uint16`, смещение фрагмента `uint16`, ID принятого сообщения `uint32`, принятое смещение `uint16`, до 192 байт данных. Поля ответа после сеанса: подтверждённый ID передачи `uint32`, принятое смещение `uint16`, ID встречного сообщения `uint32`, полный размер `uint16`, смещение фрагмента `uint16`, до 192 байт данных. Размер сообщения не превышает 768 байт; ID `0` означает отсутствие сообщения. Каждый HUD имеет отдельный буфер обмена на каждом контроллере. На HUD обмен с разными адресами также разделён; фрагменты и подтверждения одной поворотки не используются для другой.

## Поиск через API

На HUD `POST /api/hud/discover` принимает `transport=rs485`, `first=1`, `last=247`. Параметры границ необязательны; допустим диапазон `1…247`. Нужны включённые HUD UART и общая линия Modbus с маркером. Старый запрос `transport=uart` в этом режиме также запускает поиск по шине.

Читайте `GET /api/hud/peers?discovered=1`: поля `scanActive`, `scanAddress`, `scanLast` показывают ход опроса. В записях поле `busAddress` содержит адрес RS‑485 (для сетевых записей — `0`). Сохранение — `POST /api/hud/peers` с `id` найденного контроллера, выбор — `POST /api/hud/select` с этим `id`.

## Диагностика

Страница `/hardware` показывает владельца линии, число принятых и отклонённых кадров, таймауты и несовпадение параметров кольца. Те же поля вместе с конфигурацией доступны через `GET /api/hardware/modbus`. `POST` принимает `token`, `generation`, `pc`, `bus`, `address`, `node`, `first`, `count`; значения `pc` и `bus` равны `0` или `1`. Для изменения используйте актуальные `token` и `generation` из `GET /api/hardware`; успешная запись останавливает привод и перезапускает устройство.

При отсутствии связи проверьте скорость и чётность обоих портов, уникальность адресов, одинаковый диапазон ведущих, направление A/B и назначение DE. Первые запросы положения и STOP проверяйте с отключённым силовым питанием привода. После настройки проверьте остановку ручного движения при отключении HUD и восстановление обмена после возвращения участника.
