# Сеть и порты

[Документация](../index.md)

## Ethernet

На [WT32-ETH01](../boards/wt32-eth01.md) RJ45 включён автоматически, адрес выдаёт DHCP. Веб, API, rotctld, UDP и HUD используют обычные порты из таблицы ниже. Проводной адрес виден как **ETH**; Ethernet имеет приоритет перед Wi-Fi STA. Настройки Wi-Fi и резервная AP сохраняются.

## Подключение Wi-Fi

1. Подключитесь к `G5500-Rotator-XXXXXX` и откройте `http://192.168.4.1`. В роли HUD сеть называется `G5500-HUD-XXXXXX`. У нового устройства AP без пароля; задайте его в настройках.
2. В **Настройки → Сеть и подключение** укажите SSID/пароль роутера и нажмите **Сохранить и подключиться**. Пустой пароль допустим для открытой сети. В режиме общей AP сначала выберите обычную сеть в **Пульт и связь**.
3. Дождитесь «Подключено» и адреса **STA**. Он нужен для доступа через роутер; адрес **AP** — через сеть устройства. Адреса также видны на дисплее и в диагностике; у HUD они относятся к пульту.

Сохранение Wi-Fi применяется без перезапуска. AP остаётся включённой до следующей загрузки; при смене канала телефон может кратковременно отключиться. Если ответ не получен за 12 секунд, переподключитесь, обновите страницу и проверьте сохранённый SSID перед повтором. Ошибка записи настроек не меняет подключение. Смена пароля AP перезапускает устройство.

## Резервная точка доступа

В обычном режиме сети S2/S3 сохраняют AP одновременно со STA. Классический ESP32 по умолчанию включает AP только при отсутствии настроек, неудаче подключения или потере связи; после восстановления STA отключает её. Для постоянной AP выберите **Точка доступа ESP32 → постоянная AP вместе со STA** на `/hardware` и подтвердите изменение. Это требует больше внутренней памяти, особенно вместе со SPP.

Попытка STA длится до 8 секунд, повтор — через 30 секунд с сохранённой AP. Сохранение SSID ещё не означает успешного подключения. В общей сети HUD хозяин AP держит её включённой. При пересечении подсети роутера с `192.168.4.0/24` устройство при запуске выбирает другой адрес AP; актуальный адрес смотрите на дисплее или через [диагностику](../maintenance/diagnostics.md#нет-доступа).

## Порты

Значения по умолчанию; изменяемые порты смотрите в настройках или `GET /api/network`.

| Транспорт / порт | Назначение | Настройка |
|---|---|---|
| TCP 80 | Веб и HTTP API | Фиксирован; отсутствует в вариантах `noweb` |
| TCP 81 | WebSocket `/api/live` | Фиксирован; отсутствует в вариантах `noweb` |
| TCP 4533 | GS-232, rotctld и командный API | Фиксирован |
| UDP 4534 | HUD: поиск, команды, состояние | Раздел «Пульт и связь» |
| UDP 4535 | Командный API | `commandPort` |
| UDP 12040 | N1MM: приём команд | `n1mmPort` |
| UDP 13010 | N1MM: отправка положения | `reportPort`, получатели и `reportHost` |
| UDP 1234 | PstRotator: приём команд | `pstPort` |
| UDP 1235 | PstRotator: отправка ответа | Всегда `pstPort + 1` на IP отправителя |
| UDP 3232 | ArduinoOTA | Открывается на 10 минут по запросу |
| UDP 5353 | mDNS | Обнаружение сетевого порта ArduinoOTA |

Порты UDP не должны пересекаться; в сборках с вебом также зарезервирован UDP 32769 службы live. Для ArduinoOTA нужна обратная связь ESP32 с TCP-портом отправителя. [Настройка OTA](../maintenance/ota.md).

Веб и команды доступны участникам сети без отдельной авторизации. Используйте доверенную локальную сеть. Далее: [подключение программы](../integrations/index.md), [HUD](../control/hud.md) или [диагностика](../maintenance/diagnostics.md).
