# Shack Protocol v1.0

[English](README.md)

Первая реализация читает сведения об узле, каталог устройств по страницам и состояние тюнера. Эталонный обработчик для ПК принимает описание возможностей и функцию чтения снимка для каждого устройства. Он подходит для симулятора и тестов будущих адаптеров.

[Схема Protobuf](schema/shack_protocol/wire.proto) задаёт общие типы. [Манифест привязок](bindings.json) задаёт версию, транспортные форматы и общие ограничения. Из них генерируются кодек Python и параметры ограниченных структур nanopb. В каждом ответе есть ID станции, ID запроса и поддерживаемая версия. ProtoJSON может опустить скалярное значение по умолчанию, например нулевой minor. Для измерений, номера антенны и возраста отсчёта присутствие поля отличает ноль от неизвестного значения. [Правила ProtoJSON](https://protobuf.dev/programming-guides/json/) · [Параметры nanopb](https://jpa.kapsi.fi/nanopb/docs/reference.html)

| Транспорт | Привязка v1.0 |
|---|---|
| HTTP | Запрос `GET /shack/v1/hello`, `GET /shack/v1/devices` или `GET /shack/v1/devices/{device_id}/state` с заголовками `Shack-Version: 1.0` и `Shack-Request-Id`. Ответ в ProtoJSON. Для страниц каталога предусмотрены параметры `after` и `limit`. |
| USB | Запрос в ProtoJSON `UsbRequest` с тем же методом и адресом, что у HTTP. Кадр имеет вид `@SHACK <длина в байтах>\n<байты JSON>`. Ответ использует такой же кадр и содержимое ответа HTTP. Один кадр соответствует одному запросу. После разрыва соединения или тайм-аута незаконченного кадра сбросьте декодер. |
| UDP | Одна датаграмма несёт один бинарный Protobuf `Request`. После успешного разбора обработчик возвращает бинарный `Response` для того же узла назначения. |
| MQTT | Запрос в ProtoJSON `Request` публикуется в `shack/v1/{node_id}/read/{request_id}/request`. До публикации подпишитесь на соответствующую тему `…/reply`. Для обоих сообщений используются QoS 1 и отключённый retain. ID узла и запроса должны совпасть с темой. |

Предел сообщения — 1024 байта без заголовка USB-кадра. Страница каталога содержит до трёх записей в лексикографическом порядке ID. Поле `nextAfterDeviceId` при наличии служит курсором следующей страницы. ID чувствителен к регистру, занимает до 32 байт ASCII и начинается с буквы или цифры. В остальных позициях также допустимы `.`, `_` и `-`. Путь HTTP с параметрами ограничен 128 байтами. Для корректного запроса с чужой версией приходит `UNSUPPORTED_VERSION` с текущей версией. Ошибка формата вызывает `BindingError`. Сетевой обработчик может вернуть HTTP 400 или отбросить сообщение.

## Проверка

```sh
python3 -m venv /tmp/shack-protocol-venv
. /tmp/shack-protocol-venv/bin/activate
python -m pip install -r protocol/requirements.txt
python protocol/tools/generate.py --check
PYTHONPATH=protocol python -m unittest discover -s protocol/tests -v
```

Запустите генератор без `--check`, чтобы обновить сгенерированные файлы. [Эталонный пример](tests/tuner_state_vector.json) содержит один запрос и ответ в ProtoJSON и бинарном Protobuf. Тесты прогоняют транспортные привязки в памяти. Подключение HTTP/USB, аутентифицированного UDP, клиента MQTT и команд управления относится к интеграции с прошивками.
